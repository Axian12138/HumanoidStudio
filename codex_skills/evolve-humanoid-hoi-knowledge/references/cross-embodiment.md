# 源机器人学习与 G1 独立验证

本流程允许没有 G1 GT 的数据集。源 humanoid motion 是源机器人的事实参考，不是 G1 的逐帧答案。学习对象是可迁移的交互规律；验证对象始终是 G1 的实际重建结果。本文件给出实验方法，指标阈值须在 train 或独立校准材料上确定，不宣称这些阈值或方法已经得到实验证明。

## 模型和数据准备

源模型入口是 URDF，包括其引用 mesh、关节树/限位、浮动根约定、mimic 关系、关节顺序与手部版本。先检查文件闭包、长度单位和 GT motion 映射；不能凭数组长度猜模型。URDF 缺 collision 时，可从真实几何产生带版本的近似碰撞表面，但必须标记近似，不用包围盒碰撞结论冒充精确接触。

需要重心时必须有可信的各 link 质量和局部质心；需要动力学时还需要可信惯性张量、执行器和接触参数。URDF 文件存在本身不保证这些字段可用。质量缺失时仍可学习接触几何和时序，但 `inertial_quality=missing`，禁用真实 CoM 比较。骨盆或躯干中心只能标作姿态代理，不能改名为重心。

G1 使用固定版本的真实模型和实际手型，显式记录 29/43 等关节契约；不能为了兼容原例子给一个没有灵巧手的 G1 添加虚构手指。能力不足时保持问题可见，不修改 GT 物体来帮助 G1。

在数据整理阶段允许加载源模型，用 FK、几何与可用惯性把源 GT 转为带置信度的交互描述。**test 运行阶段**不加载源 URDF、不模拟源机器人，也不实时使用源机器人进行评分。冻结提取器后，由隔离的数据整理程序预计算 test 参考描述；随后评分器只接收描述、GT 场景及可用物体观测，加载 G1 检查其输出。这既保留源数据的交互事实，也满足验证只使用 G1 的要求。

提取器的规则、语义角色映射、阈值和特征选择必须先在 train 冻结。对 test 执行该提取器属于固定数据转换，不允许据 test 手工改标签、修规则或挑选更有利特征。无法可靠提取的字段标 unknown，测试前明确其适用性；不能读取结果后静默丢弃难例。

## 可迁移描述与不能直接迁移的量

| 交互信息 | 可迁移描述 | 需要 G1 自己实现或核验的量 |
| --- | --- | --- |
| 接触意图 | 推/拉/夹持/托举/释放/支撑，接触对象和作用面，接触角色与先后关系 | 具体关节角、接触 link 名、手指配合与可达姿态 |
| hand pos | 物体坐标系下的接触区域、掌面/指面朝向、接近方向、接触深度与滑移 | 腕坐标到实际接触面的偏置、手尺寸、腕角和全手扫掠 |
| 全身支撑 | 哪些接触承载、支撑切换顺序、质量向有效支撑转移的趋势 | G1 的真实质量分布、脚形、关节能力和动力学稳定性 |
| 物体效果 | 保持/移动/转动/放下的意图，世界任务目标及相对时序 | G1 的接触力、摩擦需求、实际物体响应 |
| 时间 | 接近→接触→操作→释放的事件顺序与相对相位 | 绝对耗时、关节速度与同步误差；不可任意拉伸来隐藏失败 |

先为 link 指定语义角色，例如 left_palm、right_grasp_surface、left_forearm、right_knee、left_sole。角色映射和能力要求在 train 校准。不能仅按左右手腕名字建立映射：腕关节原点不是接触点，五指手和 Dex3 也没有一一对应的指节。

如果 `T_WO` 是物体世界位姿、`T_WC` 是实际接触面坐标系，使用 `T_OC = inverse(T_WO) * T_WC` 表示接触关系。比较相对于几何表面的接触区域、法向、接近方向和接触期相对速度；物体有对称性时在预先声明的等价类内比较。可按物体/手的已知尺寸归一化描述，但实际碰撞、接触与任务目标仍用真实米制几何，不缩放场景。

源手掌轨迹不能整体平移成 G1 手腕目标。G1 应在合法区域内寻找可达接触点，保持任务需要的接触作用和物体路径，允许不同肘姿、躯干倾斜或站位。允许的改变在 train 冻结；将双手搬运偷偷换成推动，或者绕开原任务，不算等效迁移。

## 重心和支撑判断

有可信质量时，按每个模型自己的质量分布计算 `CoM = sum(m_i * p_i_com_world) / sum(m_i)`，其中 link 质心必须经过其惯性原点偏移和当前 FK 变换。承载物体是否加入组合系统要随接触阶段明确，不能一直忽略负载或把未承载物体一直加进去。

迁移的是“何时向哪个有效支撑转移质量、何时形成/释放支撑”的关系，而不是源机器人 CoM 的绝对坐标、固定偏移或同一条归一化轨迹。G1 依自己的质量、几何与任务接触建立目标。

近似准静态、共面支撑时，重心投影与支撑域的距离可以作几何筛查。动态搬运、明显加速度、手扶墙/桌等多平面接触不能用“重心落在脚的凸包内”作为充分或通用必要条件。结合接触模式、动量变化和可用物理条件评价；有动力学模型时检查接触力/力矩可行性与实际 rollout，数据不足就降低结论等级。相关动力学背景见 [MIT Underactuated Robotics 的 humanoid 接触与 CoP/ZMP 讨论](https://underactuated.mit.edu/humanoids.html)。

同理，接触面贴近、掌法向相对或形状包围只支持几何夹持假设，不能单独证明 force closure、真实承重或物体不会滑落。

## 特征与权限契约

每个预计算参考至少记录：`sample_id`、`source_group_id`、`source_robot_id/model_hash`、`extractor_version`、时间映射、各阶段接触角色/对象/区域/时序、相对姿态与滑移描述、支撑转换、可用 CoM 描述、任务目标、物体轨迹来源，以及每项的 `observed/inferred/unknown`、置信度和单位。

描述按角色归一，不携带源关节数组、源 link 网格或可恢复源模型的替代资产供测试程序加载。仅 evaluator 可读 test 参考；G1 生成器只读场景、human、允许的物体输入和冻结知识。若物体轨迹已作为生成器输入，不能单靠“复制得很准”证明知识有效，还需检查 G1 是否实现了可行接触。

对源 test 和 G1 的对比使用冻结的参考解释规则。agent 可以对比动画、接触图和数字证据，但每个判断须指出证据、置信度与结论边界；不能仅凭“看起来相似”判定或在看完输出后更换成功标准。

## train 学习与 test 判定

train 允许加载源模型重建 human→source 并对照源 GT，分析为何接触可信；再把规则应用到 human→G1，检查 G1 的可达性、碰撞、支撑和动作连续性。一个源机器人的正例只支持候选原则，不自动支持“适用于所有机器人”。记录 source-specific 参数与 target adaptation，只有原则和明确适用条件进入知识正文。每条规则区分不可更改的任务语义约束、允许G1调整的实现自由度和缺乏证据的假设；不要把源机器人习惯性的站姿误判为任务硬约束。

test 只运行 G1，分别报告三个问题：

1. **交互意图是否保留**：角色/作用面、接触顺序、持续性、物体任务结果是否符合源参考语义与人体意图。没有物体轨迹的字段标不可直接评估。
2. **G1 实现是否合格**：真实 G1 模型上的接触、全身碰撞、可达性、限位、支撑和时序是否通过；有物理证据才增加稳定性、承重和物体响应结论。无匹配 G1 GT 时不得用跨模型 MPJPE 或 joint RMSE 替代这些判断。
3. **知识是否产生增益**：相同 G1、输入、预算和种子的 baseline 与候选做配对消融。绝对不合格但稍有改善，只能记录改善，不能晋升为已验证有用的合格方案；已有合格结果但无可归因收益，也不能凭单次成功晋升新知识。

G1 的硬件不可实现、输入/模型不足、适用性不匹配、知识基本错误和证据不足分别分类。G1 不可行性筛查须使用输入与固定规则，在观察候选成绩前确定；报告其占比和整体成功率，不能事后排除失败来抬高分数。test 发现参考损坏时标记评估无效、记录队列；不在该 test 上修知识或补模型再反复试到通过。

晋升记录必须带 `source_embodiments`、`target_embodiment=G1`、G1 模型/手版本、descriptor 与 evaluator 版本、几何/运动学/动力学验证级别和独立 test 覆盖。对源模型有效而 G1 无法迁移的规则留为候选或拒绝；不能进入已通过 G1 验证的知识库。

## 行为检查示例

- 源机器人臂长较大、五指抓箱：学习双侧接触区域、法向与抬起前建立夹持的顺序；G1 按自己的手型和可达性调整站位。不能按源关节角或世界腕轨迹打分。
- 源机器人质量参数缺失：可以学习接触、接近、释放；不允许由骨盆轨迹生成“重心稳定”正例。G1 自身可信模型可单独评价质量与支撑，但不能声称与源真实 CoM 匹配。
- test 只有另一机器人的 GT：预处理输出只读交互描述，测试运行 G1 baseline/候选。没有 G1 GT 不阻断语义验证，也不生成一个伪 G1 GT。
- 某知识在源机器人上抓得好，但 G1 发生明显穿透或放手：判 G1 验证未通过；可记录状态，不把这个 test 的失败细节反馈给 train 修改知识。
