# RSS tracker 与局部 motion 修复（n2 可选动力学）

## n2 可选动力学：RSS tracker 播放与局部 motion 修复

仅在本次范围包含动力学时使用本页；先确认场景自由静置、物理参数及控制器依赖。加载 n1 场景和 n2 运动学参考，并直接打开 [本地接口](local-interfaces.md) 的 RSS 修复页面供操作者交互；除非用户明确要求 AI 诊断或自行修复，不先替操作者审查能否修复。**n2 动力学 默认把 retarget motion 机器人作为青色半透明虚影叠在同一三维场景中**，按当前物理 slot 对应的源帧更新，实体机器人显示 tracker 的实际物理状态；明确标注虚影不是原始人体。页面以安全初始帧的暂停状态开始。按播放后从页面上**当前 RSS 物理状态**逐步推理 ScaleBridge `WholeBody-14`（mode 7），并推进机器人和物体碰撞动力学。时间轴仅允许选择已经模拟并保存的物理状态，不允许任意跳到 reference 帧。记录 tracker 指令、实际全身 qpos/qvel、身体状态、物体/柔性状态和源帧映射。当前 checkpoint 需要 CUDA。

五点接管 `VR-5`（mode 4）控制骨盆、左右手腕、左右脚踝。场景圆点或页面对应文字双击开启目标位姿控件，拖动位移轴与旋转环设置该 link 的世界系 6D 目标；半透明的手、脚或骨盆网格显示目标姿态。每个 link 独立设置线速度和角速度，默认分别为 0.30 m/s 和 1.0 rad/s；多个 link 可同时修复。每次 inference 都用**实测当前位姿到固定目标**判断方向与停止条件，并让独立的命令位姿按速度/角速度上限累积前进，再从命令位姿生成 offsets 0、1、2、3、4、32 的 future target ramp。不要把 future 的 slot 0 每帧重置成实测位姿；机器人跟不上时这会抹掉 tracker 需要追赶的误差。实测位置或旋转接近目标时该分量速度变零，所有 future slot 受总位移预算约束。未修复过的 link 跟随原参考；关闭目标控件使该 link 保持当前实测位置与旋转。若某手腕平时使用 refmotion PID，进入该手腕的 6D 修复时须交还 tracker 控制。页面只有一个播放/暂停键：暂停时先设置修复，再按它提交并播放。每个控制帧保存机器人、物体和柔性粒子状态 slot；回退和播放已有白色缓存直接加载这些状态。新修复仅令当前 slot 后的缓存失效，保留连续前缀；只有修复命令改变才在时间轴留下起始圆点，圆点可以直接点击回退。双手分别用一个连续开合滑杆控制，100% 对应各自的接近限位闭合目标，不能直接取未执行抓取的另一只手在源动作里的关节值。完成接管时操作者打开恢复选帧，在同一场景对照当前物理机器人与青色参考骨架，选择相近的 refmotion 帧后按播放开始插值恢复。

接管使输出帧数可能不同于源动作。恢复从暂停的实测身体 qpos 到操作者选定的参考帧生成插值目标，但双手 Dex3 保持进入恢复时的闭合命令，不随全身插值回源动作；有手动开合覆盖时，恢复结束后继续保持，直到操作者明确修改。时长可为零，此时直接从当前物理状态 track 衔接参考，不能瞬间改写物理 qpos。输出按原参考、接管实测 qpos、恢复插值参考、恢复后的原参考四段拼接；恢复段同时保留实际物理 rollout，不能把目标插值与实测状态混称。保留逐输出帧的源帧索引和阶段。`candidate_motion.npz` 仍是未验收候选，须检查接缝、足滑、速度、加速度、接触和物体响应；不可仅凭导出成功晋升训练集。

**本轮动力学审查：**局部动作与原人体/任务意图一致，暂停/回滚后状态可复现，接管及恢复接缝可审查。若 tracker 无法稳定接近参考，回到 n2 运动学 改参考或诊断模型/控制，不把大误差伪装为局部编辑。

场景/碰撞/物理参数导致失败时回 n1 修正，再重跑受影响片段；无需将每次失败都改成 motion 问题。
